# Architecture Governance

[English](README.md) · [한국어](README.ko.md) · [简体中文](README.zh-CN.md) · **日本語**

**既存のアーキテクチャを守りながらコードを変更するための Claude Code プラグインです。**

Architecture Governance は、ソフトウェア変更の計画・実装・監査・レビュー・検証を一つの Skill にまとめた Claude Code プラグインです。ある振る舞いの責任がどこにあるか、どの箇所を変更すべきか、作業の完了を宣言する前にどのような検証根拠が必要かを確認できるようにします。

新たなアーキテクチャを押し付けるものではありません。設計上の判断では、対象プロジェクト自身の規範文書・契約・テストを正とします。

## なぜ必要なのか？

コードがコンパイルでき、一部のテストに通っていても、設計に違反することがあります。たとえば、第二の正規データを作る、公開契約を迂回する、未定義のエラー処理方針を独断で追加する、コマンドの成功を正しさの証明と取り違える、といったケースです。

Architecture Governance は、こうした問題を開発の各段階で確認できるようにします。

- **責任の所在を特定する：** 新しい抽象化を追加する前に、既存の責務と契約を調べます。
- **振る舞いの意味を理解する：** 必要に応じて状態・識別子・順序・失敗・復旧・依存関係の境界を確認します。
- **リスクに応じて計画する：** 小さな修正には軽い手順を、公開契約やシステム全体の規則の変更には厳密な検討を適用します。
- **変更内容を検証する：** 正常系だけでなく、実際の Git diff と失敗経路も確認します。
- **検証の根拠を区別する：** 定義済み・実装済み・実行済み・実際に立証された事項を混同しません。

## インストール

Claude Code で次のコマンドを実行します。

```bash
claude plugin marketplace add onetwohour/claude-plugins
claude plugin install architecture-governance@onetwohour
```

インストール後、新しい Claude Code セッションを開始してください。

## はじめに

Skill に作業内容を伝えます。

```text
/architecture-governance:architecture-governance plan 保存失敗後の安全な復旧処理を設計する
```

既存の設計に従って実装する場合：

```text
/architecture-governance:architecture-governance implement エディタ再構成後の古い応答の処理を修正する
```

設計や変更内容を確認する場合：

```text
/architecture-governance:architecture-governance audit 設計文書と実装のアーキテクチャ違反を調査する
/architecture-governance:architecture-governance review 現在の Git diff をレビューする
```

関連する作業では、Claude がこの Skill を自動的に選択する場合もあります。特定のワークフローを使いたい場合は、明示的に呼び出してください。

## ワークフロー

| モード | 内容 |
| --- | --- |
| `plan` | 責任の所在・契約・代替案・影響範囲・検証計画を整理します。 |
| `implement` | 既存の責務を調査したうえで実装し、diff のレビューと関連チェックを行います。 |
| `audit` | 実装上の違反だけでなく、規範文書同士の矛盾も調査します。 |
| `review` | 提案または実施された変更をアーキテクチャ上の要件と比較します。 |
| `verify` | 適用できるチェックを実行し、得られた根拠と未検証の部分を説明します。 |
| `project` | 既存の正規情報源から、プロジェクトの状態や未完了作業の派生ビューを作成します。 |
| `adopt` | 既存リポジトリのルールや検証手段に、このワークフローを導入するための支援を行います。 |

すべてのモードは**一つの Skill** に含まれます。モードを指定しない場合は原則として `plan` が選ばれますが、依頼の意図が明確であれば適切なモードを使用します。

## 保証しないこと

Architecture Governance はエージェントの開発手順を支援するものであり、プロジェクト固有のアーキテクチャリンター、テスト、セキュリティの強制機構、CI を置き換えるものではありません。すべての変更で Skill が必ず呼び出されるとは限らず、文書によるレビューだけですべての意味的な不変条件を証明することもできません。

また、テストを見つけたことやコマンドが成功したことは、その契約全体の正しさを証明したこととは異なります。未実施の検証や結論の出ていない項目は、完了扱いにせず明示する必要があります。

強制すべきルールは、**対象プロジェクト自身の CI と検証ツール**で適用してください。
